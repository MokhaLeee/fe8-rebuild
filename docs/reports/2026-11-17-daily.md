## 0. 起点与总体思路

起点是 `a53d6aa`（`tag: decomp-baseline`）的一次性快照：7,028 个跟踪文件、
946,965 行插入、359 个 `.c`（342,846 行）、174 个头文件、`ldscript.txt` 1,031 处
对象级定位、1,293 处 `incbin "baserom.gba"`。

**昨天最重要的判断是「顺序」**，不是任何单个改动：

| 判断 | 依据 |
|---|---|
| 字节门禁现在不能扔 | 它是唯一能证明「重构没改坏游戏」的自动化判据，全量构建只要 ~46 s |
| 先做「纯移动 / 纯格式」，后做「合并 / 换编译器」 | 合并会改变目标文件边界 → 链接顺序变 → 地址变；纯移动不改变边界 |
| 链接脚本是对象级钉死的 | 1,031 处 `src/xxx.o(.text)`，**行序即地址**，移动文件必须保序改写 |
| `baserom.gba` 暂时不能删 | 还有 1,293 处 `.incbin` 依赖它，约占 ROM 1.07 MB |

所以昨天只做了「可回退、可逐批验证」的四类事：清理、风格、纯移动、素材移动。

## 4. 全量内核风格改造（昨天最重的一段）

**原则**：只改空白与括号位置，不改语义、不改结构、不折行；每批 `make check`。

### 4.1 第一轮：clang-format 路线，失败并全部回退

先试点 5 个文件，再一次性转 66 个 `banim-*.c`，两次都提交了。随后**全部 revert**（`db553c6`，72 文件）。

废掉的原因（都是实测）：

| 问题 | 现象 |
|---|---|
| 模板误判 | `i < sp08 >> 0x13` 被重排成 `i<sp08> > 0x13`，agbcc 直接 `syntax error` |
| 语句表达式 | `({(sp04 * x >> 0x14) + 1;})` 被当初始化列表加空格，agbcc 拒绝 |
| 宏前缀声明 | `EWRAM_OVERLAY(banim) struct Anim *gAnims[4] = { NULL };` 被拆成两行（`ColumnLimit: 0` 触发） |
| **验证方法本身失效** | 用「剔除空白后比较」验证——`>>` 和 `> >` 剔除空白后完全相同，**最危险的一条恰好查不出来** |

第三条可以换配置规避，前两条不行；而且 `ColumnLimit: 0` 本身就是错设置。

### 4.2 第二轮：手改 35 个文件，建立基准

手改一批后，把这 35 个文件当基准去回归 clang-format：**只复现 7 个**。
结论：clang-format 不可用，且不能用它验证自己。

### 4.3 第三轮：5 个专用脚本 + 手工

| 工具 | 作用 |
|---|---|
| `tools/style/indent-tabs.py` | 行首空格 → Tab（带字符串/注释词法状态，不误改字面量） |
| `tools/style/brace-kr.py` | Allman → K&R；靠**花括号深度**区分函数体（不并）与控制块（并） |
| `tools/style/decl-blank.py` | 局部声明后空行、指针星号贴变量 |
| `tools/style/strip-trailing.py` | 去行尾空白 |
| `tools/style/token-check.py` | **token 级**比对（先切 token 再比，`>>` 与 `> >` 判不同） |

判定标准改为三重：**token 级比对 + 函数计数 + ROM sha1**。

### 4.4 两条必须记住的例外

1. **不许删单语句大括号**。`src/mu.c` 的 `ResetMuAnims` 实测：删掉后 agbcc 寄存器分配变化，
   `push {r4-r7,lr}` 变成 `push {r4,r5,lr}`，ROM 不再一致。本阶段只改大括号**位置**。
   （口诀：动位置安全，删大括号不安全。）
2. **4 个大表不转**：`data_characters.c` / `data_classes.c` / `data_terrains.c` /
   `events_udefs.c`，合计 96,360 行，本身 4 空格与 8 空格混排，转了是半 Tab 半空格，
   且后面数据整理要重写，此处重排无收益。

## 5. 目录重组：只移动，不改内容

### 5.1 为什么不能直接 `git mv`

`ldscript.txt` 把每个目标文件钉在固定地址，**行序即地址**；而且引用对象路径的脚本是**四个不是三个**：
`ldscript.txt`、`linker_script_sound.txt`、`linker_script_banim.txt`、`sym_iwram.txt`（被 `INCLUDE` 进来）。

### 5.2 做法

1. `tools/refactor/gen_mapping.py`：把「文件 → 模块目录」规则集中在一处（显式表 + 前缀规则），可重跑；
2. `tools/refactor/move_src.py`：`git mv` + 对四个脚本做**保序**字符串替换（长名先替换，避免前缀误匹配）；
3. 分 8 批移动，**每批一次 `make check`**；
4. 同步改 `Makefile` 的逐文件编译选项路径、`.gitignore` 通配层级，清理陈旧的 `.o`/`.s`（本次 626 个）。

### 5.3 四个坑（全部踩过并修好）

| 坑 | 症状 | 处理 |
|---|---|---|
| 漏了 `sym_iwram.txt` | 链接报 `cannot find src/rng.o` | 改写范围扩到四个脚本 |
| `Makefile` 逐文件选项按旧路径写 | `agb_sram.o` +0x18、`m4a.o` +0x10，后面整体平移 | 覆盖规则路径跟着批次同步改 |
| 旧路径 `.o` 残留被一起链接 | `multiple definition` | 清理「旁边没有同名 `.c`」的产物，**排除** 4 个手写汇编源 |
| 清理脚本误删源码 | `rom_header.s` 等 4 个汇编源消失 | 白名单：`rom_header` / `crt0` / `m4a_1` / `libagbsyscall` |

定位第 2 个坑的方法值得留档：`git archive HEAD | tar -x -C /tmp/base` 导出已提交版本单独构建，
**diff 两张 `fireemblem8.map`**，直接看出哪个对象 `.text` 尺寸不对。
